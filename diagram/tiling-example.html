Event model wiring: command → event in the same slice; event → later read model. See Help for the full rules.

Event model connector playground

Each column is a slice on the timeline. The upper cell is a command or read model; the lower cell is where an event lands. Arrows in the middle band are the tiled connectors between them.

How to wire

  • Click a valid source, then a valid target.
  • Click the same cell again (or Clear selection) to cancel.
  • With an event (lower) selected, click to the right of the last slice to add a later slice and project that event into the new upper (read model).

What you can connect

  • Command → event: only same-slice upper → lower (centered down arrow). You never write an event from a different slice’s command.
  • Event → read model: lower → upper on a later slice only (time moves right; no leftward or same-slice projections).

Causality locks

  • An event cannot project until it exists: always wire same-slice command → event first, then you may join from that lower.
  • A command that has already written its event (upper with an outgoing join) is locked — nothing more to or from it.
  • A read model upper that already has an incoming projection cannot issue a command (it can still take more event inputs).

Colors (event-model palette)

  • Event — lower with an incoming command arrow
  • Command — upper that wrote an event
  • Read model — upper fed by one or more events

Slices on the timeline

  • Add blank slice at end appends the next step in time.
  • Hover a slice boundary to reveal + and insert a blank slice; later indexes shift so existing wiring stays consistent.
  • With an event selected, inserting a slice to its right (via + or the right-side click zone) also projects that event into the new upper.

Connector routing

  • Write path: same-slice command → event is a centered vertical shaft into the event.
  • Projection path: from the event, joins leave to the right of that shaft, travel on a horizontal band, and rise into the target read model. The first input to a read model arrives on center; further inputs sit one tile further right without moving the first.
  • Leftness: projection bands are ordered by fromSlice + toSlice. Smaller sum sits higher (e.g. event in slice 1 → read model in 3 sums to 4 above 2→3 summing to 5), which prefers left-origin runs on top and reduces hops.
  • Where a projection crosses another slice’s write-path shaft, a hop tile bridges the crossing.
