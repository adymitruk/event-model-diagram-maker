Event model connector playground

Each column is a slice on the timeline. The upper is a command or state view (read model); the lower is where an event lands. Connectors in the middle band are discrete tiles — never overlapping.

How to wire

  • Hover a blank upper for click to make command and event, then click once — same-slice command → event.
  • Hover an event for click to select, then click again on where to connect to. Click it to select, then click a later upper (hover shows click to connect the selected event to a state view here), or click to the right of the last slice to add a slice and project into it.
  • Click the selected event again to cancel.

What you can connect

  • Command → event: only same-slice upper → lower (centered down arrow).
  • Event → state view: lower → upper on a later slice only (time moves right; no leftward or same-slice projections).

Causality locks

  • An event cannot project until it exists: make command → event first, then you may join from that lower.
  • A command that has already written its event is locked — nothing more to or from it.
  • A state view upper that already has an incoming projection cannot issue a command (it can still take more event inputs).

Hover & highlight

  • Hover a connected card to double-highlight it and its path endpoints, and to blacken that join’s tiles.
  • Hover a connector tile to highlight that join and both end cards the same way.
  • Click a connector to bring any end that is partly out of view fully into the viewport (scrolls that slice).
  • Connectors are grey when idle and black when highlighted.
  • A hop (horizontal crossing a vertical) highlights each side independently: the vertical for the write/stub/rise join, the bridge for the projection.

Colors (event-model palette)

  • Event — lower with an incoming command arrow
  • Command — upper that wrote an event
  • State view — upper fed by one or more events

Slices on the timeline

  • Load example fills the board with 15 slices and a mix of writes, multi-input state views, and hops.
  • Hover a slice boundary to reveal + and insert a blank slice; later indexes shift so existing wiring stays consistent.
  • Hover the area to the right of the last slice for an Add slice pop-out. With an event selected, that also projects into the new upper.

Connector routing

  • Write path: same-slice command → event is a centered vertical shaft into the event.
  • Projection path: from the event, joins leave to the right of the write shaft, travel on a horizontal band, and rise into the target state view. Multiple inputs are centered as a group; the write shaft stays locked to center and pushes other columns aside.
  • Leftness: projections claim bands in fromSlice + toSlice order (smaller sum higher). A worse claim cannot sit above a better one; a line moves up only when there is room (no elbow clash at another join’s source/dest).
  • Where a horizontal crosses a vertical, a hop tile owns that cell (draws both segments). Vertical shafts break around hops — no stacked tiles.

Event-sourced history

  • Branch and History live in the top toolbar next to Clear board / Help.
  • Every insert, join, and clear is an event on the active branch. The board is a projection of events up to the slider position.
  • Slide the History slider to view any past version. Changing the board while not at the tip forks a new branch.
  • Use the Branch dropdown to switch to another branch’s head.
